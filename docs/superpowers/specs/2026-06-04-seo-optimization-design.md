# Дизайн SEO-оптимизации

## Контекст

Сайт updev.ru работает на Hugo, использует русский контент и тему Gokarna как Git submodule. Часть шаблонов уже переопределена локально в `layouts/`. Сейчас SEO-метаданные генерируются в partial темы `themes/gokarna/layouts/partials/head.html`.

Реализация не должна менять файлы темы в submodule. Все изменения SEO-логики должны находиться в локальных файлах сайта.

## Цель

Улучшить SEO-метаданные для основных страниц сайта:

- Главная страница.
- Список публикаций.
- Отдельные страницы публикаций.
- Список проектов.
- Отдельные страницы проектов.
- Страница технического радара.

Оптимизация должна затронуть `meta description`, Open Graph, Twitter card metadata, canonical links и page titles. Видимый контент страниц в рамках этого прохода не меняется.

## Стратегия Title

Точные русские формулировки `<title>` откладываются на отдельный редакторский проход. Реализация должна поддерживать контекстные шаблоны заголовков, но финальные тексты должны быть утверждены отдельно до начала кодирования SEO-логики.

Нужные контексты заголовков:

- Главная страница: персональный бренд Сергея Ладыгина, lead development и менторство.
- Список публикаций: публикации Сергея Ладыгина.
- Отдельная публикация: название публикации плюс суффикс публикации Сергея Ладыгина.
- Список проектов: проекты Сергея Ладыгина.
- Отдельный проект: название проекта плюс суффикс проекта Сергея Ладыгина.
- Технический радар: тех радар Сергея Ладыгина.

Правила заголовков должны быть централизованы, чтобы формулировки можно было менять без редактирования каждого markdown-файла.

## Стратегия Description

Описания должны храниться в поддерживаемых метаданных контента:

- Главная страница: site-level описание в `config.toml`.
- Список публикаций: section-level описание в новом файле `content/articles/_index.md`.
- Список проектов: section-level описание в `content/projects/_index.md`.
- Тех радар: section-level описание в `content/radar/_index.md`.
- Отдельные публикации и проекты: использовать `.Description`, если поле задано; иначе использовать `.Summary`, контент страницы или site-level fallback.

Тексты описаний должны быть естественными SEO-описаниями на русском языке без переспама ключевыми словами. В них можно упоминать релевантные темы: Go, backend-разработка, Strapi, observability, OpenTelemetry, Docker Swarm, AI-инструменты, PHP-библиотеки, API и менторство.

## Архитектура

Нужно создать локальный override `layouts/partials/head.html` на основе текущего partial темы Gokarna.

Override должен:

- Сохранить поведение темы для стилей, скриптов, canonical links, fallback-изображения аватара, keywords, Open Graph image, Twitter image и `customHeadHTML`.
- Заменить вычисление title на локальную централизованную логику.
- Заменить вычисление description на локальную fallback-цепочку.
- Использовать вычисленные title и description одинаково для:
  - `<title>`
  - `<meta name="description">`
  - `<meta property="og:title">`
  - `<meta property="og:description">`
  - `<meta name="twitter:title">`
  - `<meta name="twitter:description">`

SEO-метаданные не должны дублироваться через `customHeadHTML`.

## Изменения Контента

Добавить или обновить front matter описания только там, где они обслуживают SEO-метаданные:

- Создать `content/articles/_index.md`.
- Обновить `content/projects/_index.md`.
- Обновить `content/radar/_index.md`.
- Добавить поле `description` в каждую существующую публикацию.
- Добавить поле `description` в каждую существующую отдельную страницу проекта.

Описания карточек проектов в `content/projects/_index.md` можно улучшать только если это не ухудшает видимый текст карточек. Если для SEO нужен другой текст, нужно использовать отдельное поле для мета-описания, а не менять карточку.

## Поток Данных

Для каждой сгенерированной страницы:

1. Hugo определяет текущую страницу и тип контента.
2. Локальный head partial вычисляет SEO title из контекста страницы и утвержденной title-формулировки.
3. Локальный head partial вычисляет SEO description из metadata, summary, content или site-level fallback.
4. Одни и те же значения попадают в стандартные SEO-теги, Open Graph и Twitter-теги.
5. Canonical URL остается `.Permalink`.

## Fallbacks

Если у страницы нет явного description, сборка все равно должна вывести валидное описание через fallback-цепочку.

Если у страницы нет изображения, Open Graph и Twitter images должны продолжить использовать текущий fallback на аватар.

Если позже появится новый тип контента, fallback title должен оставаться равным title страницы или site title, как в текущем поведении темы.

## Проверка

Запустить production build:

```bash
hugo --minify
```

Проверить HTML для:

- `/index.html`
- `/articles/index.html`
- одной сгенерированной страницы публикации
- `/projects/index.html`
- одной сгенерированной страницы проекта
- `/radar/index.html`

На каждой странице должны быть ожидаемые:

- `<title>`
- `<meta name="description">`
- `<meta property="og:title">`
- `<meta property="og:description">`
- `<meta name="twitter:title">`
- `<meta name="twitter:description">`
- `<link rel="canonical">`

## Вне Скоупа

- Изменения видимого layout.
- Настройка Search Console или аналитики.
- Structured data JSON-LD.
- Кастомизация sitemap сверх стандартного поведения Hugo.
- Финальное редакторское утверждение точных формулировок `<title>`.
